# Coding Standards

This document records the conventions already used in `src/` and `tests/`. Follow them in new code. Biome enforces formatting and lint; this file covers what Biome does not.

## 1. General Code Style

- Prefer clarity over cleverness. Keep functions small and focused.
- Reuse existing helpers before writing new ones. Shared utilities live in `src/lib/`.
- Remove imports, variables, and functions that a change leaves unused.
- Use early returns instead of nested conditionals.
- Single-statement `if` bodies may omit braces and stay on one line:

  ```ts
  if (info.menuItemId !== 'open-markdown-reader') return;
  ```

## 2. Naming Conventions

| Item                          | Convention                        | Example                                 |
| ----------------------------- | --------------------------------- | --------------------------------------- |
| Variables and functions       | `camelCase`                       | `readSettings`, `activeBaseUrl`         |
| Module-level constants        | `UPPER_SNAKE_CASE`                | `SETTINGS_KEY`, `CUSTOM_CSS_MAX_LENGTH` |
| Types, interfaces, components | `PascalCase`                      | `ReaderState`, `StatusBanner`           |
| Component props               | `<Component>Props`                | `StatusBannerProps`                     |
| Files                         | `kebab-case`                      | `file-url-tree.ts`, `status-banner.tsx` |
| Unit tests                    | `<module>.test.ts` or `.test.tsx` | `tests/unit/recent.test.ts`             |
| E2E tests                     | `<feature>.spec.ts`               | `tests/e2e/reader.spec.ts`              |
| Storage keys                  | versioned string                  | `settings:v1`                           |

## 3. Formatting Rules

Biome owns formatting. Run `pnpm format` before committing; `pnpm lint` must exit 0.

- Indentation: **2 spaces**
- Line length: **140 characters**
- Quotes: **single** in TypeScript; JSX attributes use double quotes
- Semicolons: always
- Trailing commas: on multiline literals and argument lists
- Encoding: UTF-8, final newline

## 4. TypeScript

- `strict` mode is on. Use primitive types `string`, `number`, `boolean`; never `String`, `Number`, `Boolean`, or `Object`.
- Use `interface` for object shapes such as props and store state. Use `type` for unions, aliases, and mapped types.

  ```ts
  export type Mode = 'read' | 'edit' | 'split';
  export interface StatusBannerProps { banners: NonNullable<Banner>[]; onRetry(): void }
  ```

- Model variants as discriminated unions on a `kind` field, as in `TreeNode` and `Banner`.
- Use `import type` or inline `type` modifiers for type-only imports.
- Prefer `unknown` plus narrowing over `any`. Validate untrusted data with Zod mini, `import * as z from 'zod/mini'`, and fall back to defaults with `z.catch`, as in `src/lib/settings.ts`.
- Prefer optional chaining and explicit checks over non-null assertions `!`.
- Prefer named exports. Use `export default` only where WXT requires it: entry point `App` components and `defineBackground` or `defineContentScript`.

## 5. Imports

- Inside `src/`, import with relative paths: `'../lib/settings'`.
- The `@/` alias is used only by the shadcn/ui primitives in `src/components/ui/`, as generated by the shadcn CLI.
- Tests import from source with relative paths: `'../../src/store/recent'`.
- Order: external packages first, then local modules.

## 6. React and UI

- Write components as named function declarations: `export function Toolbar(props: ToolbarProps) {}`.
- Build UI from the primitives in `src/components/ui/`. Add new primitives with the shadcn CLI so they match `components.json`.
- Style with Tailwind utilities; merge class names with `cn()` from `src/lib/utils.ts`. Use the CSS files in `src/styles/` for reader layout and rendered Markdown.
- Use design tokens such as `var(--foreground)` and `var(--border)`; avoid hard-coded colors.
- Honor `prefers-reduced-motion` for every transition.
- State: Zustand stores live in `src/store/`. The reader store is created per page with `createReaderStore` and provided through `ReaderStoreContext`.
- UI strings belong in `src/i18n/en-US.ts` and are read with `t('section.key')`.

## 7. Comments and Documentation

- Explain why, not what. Most functions need no comment.
- Use a one-line `/** ... */` doc comment for exported functions with a non-obvious contract:

  ```ts
  /** Stable string for a plugin config; it keys the parser cache and every block key. */
  ```

- Use `//` comments for local reasoning, such as browser quirks or workarounds.
- Every `TODO` names its exit condition: `// TODO: drop this shim when markdown-it-multimd-table (4.2.3) stops calling md.utils.assign.`

## 8. Security

- All rendered HTML passes through `sanitize()` in `src/render/sanitize.ts`. Never assign untrusted HTML to the DOM another way.
- When the sanitizer allow-list changes, add a case to `tests/fixtures/markdown/xss.md` or `tests/unit/sanitize.test.ts`.
- Accept URLs only through the checks in `src/source/url.ts`.
- Keep everything bundled. The MV3 CSP forbids remote code, so do not load scripts or styles from a CDN.
- Do not add extension permissions without updating the justification in `CHROMEWEBSTORE.md`.

## 9. Error Handling

- Handle failures explicitly. Surface user-visible errors through the reader banner state rather than throwing to the console.
- Use `try`/`catch` with an empty binding where the error value is unused: `catch { return false; }`.
- Parse stored or remote data defensively and fall back to defaults instead of crashing.
- Mark intentionally floating promises with `void`.

## 10. Tests

- Add or update a unit test in `tests/unit/` for every behavior change. Vitest runs with `happy-dom`.
- Use `describe` and `it` with sentences that state the behavior: `it('deduplicates URLs, puts newest first, and keeps at most 20')`.
- Inject dependencies such as storage areas instead of mocking modules where the code allows it.
- Keep tests deterministic: no network, no unseeded randomness, no real timers where fake ones work.
- Cover browser-only behavior in `tests/e2e/` with the fixtures in `tests/e2e/fixtures.ts`. Playwright runs with one worker so the performance gate stays stable.
- Record anything that cannot run headless in `docs/manual-checklist.md`.

## 11. Commits and Reviews

- Use Conventional Commits with a scope: `feat(reader): ...`, `fix(settings): ...`, `docs(plans): ...`.
- One logical change per commit.
- Before a commit, run `pnpm typecheck`, `pnpm lint`, and `pnpm test`. Run `pnpm test:e2e` for UI or extension behavior changes.
- Larger features start with a design and a phased plan in `docs/plans/<feature>/`.

## 12. Known Inconsistencies

The codebase diverges from these rules in places. Fix them when you touch the surrounding code; do not open sweeping cleanup changes. Counts are from `pnpm lint` on 2026-11-10, which exits 0 with 208 warnings and 3 infos.

Other drift:

- Some UI strings are hard-coded instead of coming from `src/i18n/en-US.ts`, for example `Retry` and `File changed on disk` in `src/ui/status-banner.tsx` and the badge title in `src/entrypoints/background.ts`.
- Import order is not enforced; Biome's `organizeImports` is off.
